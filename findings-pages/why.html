Why might one stack be faster?

Both stacks follow tilt commands almost the same way. The shared tilt-lead design limits the lap time more than the choice of stack.

We measured this from the recorded 33 s flights. We can show where the stacks differ. We still cannot show which part of the flight software causes the difference.

Three things stand out:

  1. Both stacks are about equal. Both reach the commanded tilt about 170 ms later, at full size. That matches 1/K for the shared gain K = 6/s, which is 167 ms. Betaflight is about 5 to 10 ms quicker in roll. That is close to the 4 ms the recordings can resolve.
  2. CogniPilot still had a slightly smaller largest error. It was 8 to 25 mm lower in all 11 distinct matched flights. Its tilt response also fits the simple model about four times more closely. We do not know which part of the software causes this.
  3. Tilt lead is the limit, not tilt delay. With lead off, CogniPilot's tilt trails its target by the full 172 ms, yet its largest error drops from 0.71 m to 0.48 m. Following the tilt target closely does not give the best path at this speed. We have not tested why. One possibility is that the shared position controller already plans ahead, so the lead adds the same correction twice.

Does Betaflight's setup hold it back?

Possibly, for landing. We flew the same failing case twice with only the motor protocol changed. Firmware, plant and runner program were the same.

Matched protocol test: 35 s lap, harsh noise, seed 2, lead on
Motor protocolControl loopTypical error (m)Largest error (m)Landing

Tracking barely changed, so the protocol probably does not change the lap-time result. Landing did change. This is one matched pair, so it is a strong lead, not proof. It also does not test the real motor signal, only how the protocol setting changes Betaflight's scheduling in this simulation.

What does "8 kHz versus 1.6 kHz" really mean?

It does not mean Betaflight senses or controls five times faster. It is how often the simulator exchanges messages with each stack. Select a row to see what it means.

The message difference could change timing by up to about 0.5 ms. The drones take about 170 ms to follow a tilt command, so this is a limit we disclose, not a likely explanation. (The 0.5 ms figure is an estimate from the exchange schedule, not a measurement.)

    Is the same gain fair to both stacks?

    Using K = 6/s for both is the same rule. In the earlier, non-ARM step test it did not produce the same step response:

    In the 33 s flights, though, both stacks followed tilt commands with nearly the same delay. Nobody has retested K = 6/s on this test bed. Changing it would need a rebuild and a full rerun for both stacks, so we keep it and say so.
